# who-builds-what: design spec

*17 August 2026. Free public tool by Omri Pitaru. Approved in session after four
design rounds (form factor, grill depth, storage, name) and two user catches
(visibility layer, Monday over GitHub).*

## The problem, in one line

Inside most companies, many people are building AI projects, no one knows who is
building what, work gets duplicated, and managers discover projects they never
approved. The launch hook: "ever had two people build the same project without
their manager knowing?"

## What it is

A free kit that gives any Monday.com company an AI-project registry:

1. A **Monday board template** holding one item per AI project.
2. An **AI interview** (3 minutes) that replaces the registration form, with an
   optional deeper "grill."
3. A **script** that flags duplicate-looking projects and writes a manager
   digest at whatever cadence the org picks.

No servers, no accounts of ours, no telemetry. Data lives in the org's own
Monday and flows through the org's own AI accounts.

## Users and stories

- **Dana (builder, non-technical):** built an AI thing for her team. Runs the
  interview in whatever AI chat she uses, gets five crisp answers, pastes them
  into the board's shareable Monday form. Three minutes, no account needed.
- **A Claude Code user:** says "register my AI project"; the skill interviews
  them and writes the board item directly through Monday's API, checking for
  similar existing items on the way.
- **The manager:** receives a digest (daily, weekly, their call): new projects,
  projects with no manager sign-off, stale projects, and duplicate-suspect
  pairs. Reads it in Slack or mail, opens the board only when something needs a
  decision.
- **The registry keeper (an internal-AI person like the author):** duplicates
  the template, shares the form link, sets the digest schedule, owns adoption.

## Components

### 1. Monday board template
Columns: Project name, Owner (person), Team, Status (idea / building / in use /
retired), Tools & models (tags), Data it touches (tags: e.g. customer PII,
internal docs, public only), Manager aware (yes / no / pending), Notes link,
Created, Last updated. Views preconfigured: by team, by status, needs-approval
filter. The board's WorkForm is enabled and maps 1:1 to the interview's output.
Shipped as a Monday template link plus a documented manual-setup fallback (column
list in the README) in case template links change.

### 2. The interview (two doors, one schema)
- `skill/register-ai-project/SKILL.md`: Claude Code skill. Quick intake, five
  questions, one at a time: what are you building; who is it for and who owns
  it; what tools and models; what data does it touch; does your manager know.
  Then: writes the item to the board via Monday API (token from env), after
  querying existing items and surfacing close matches ("this looks like Dana's
  pipeline project - same thing?"). Then offers the optional grill.
- `prompts/interview.md`: the same interview as a paste-anywhere prompt
  (ChatGPT, Gemini, claude.ai). Output: the five answers formatted to paste
  into the Monday form fields.
- **The grill (optional, after intake):** ~10 minutes, modeled on the author's
  grilling method (relentless, one question at a time, recommended answer per
  question): duplication probes, data-exposure edges, who maintains it when the
  owner is away, what would kill it, what it costs. Grill output appends to the
  item's notes. Written fresh for this repo; no text imported from any employer
  framework.
- **No-secrets rule, enforced in both doors:** the interview records data
  CATEGORIES, never actual data, keys, or personal details, and says so if the
  user volunteers them.

### 3. The script: `wbw.py`
Standard-library Python only (urllib for Monday's GraphQL API). Subcommands:
- `wbw.py digest --board <id>`: renders the manager digest as markdown: new
  items since last run, manager-aware != yes, stale items, duplicate-suspect
  pairs. Output to stdout/file; the org pastes or pipes it to Slack/mail.
- `wbw.py dedup --board <id>`: token-overlap similarity on name + description +
  tools; flags pairs above threshold. No embeddings in v1.
Config (flags or a small config file, nothing else): `--cadence daily|weekly`
(affects "since last run" window framing), `--stale-days N` (default 60),
`--dedup-threshold` (default conservative). Scheduling is the org's choice:
by hand, cron, Make, or a GitHub Action example we ship.
Monday-native automations cover stale-item nudges without the script; the
README says so.

### 4. Repo and docs
Public GitHub repo `who-builds-what` (code, prompts, README, examples). The
USER deploy story never requires git: duplicate board, share form, run
interview. README structure: the observation (the hook), 3-step deploy, the two
doors, digest setup with cadence choice, the trust section (data boundaries in
five lines), honest scope line ("this solves the self-reporting half; the
interview makes reporting cost three minutes"), v2-on-demand note (Notion,
Sheets, other platforms if people ask). MIT license. `examples/` holds five
fictional projects rendered as a demo board screenshot set for the posts, plus
sample digest output. Small stdlib unittest file for the script; GitHub Action
runs it for the badge.

## Data boundaries (the trust section, spec form)

- Entries live in the org's Monday. The interview runs on the org's own AI
  accounts. The script runs wherever the org runs it, calls only Monday's API
  with the org's token, and has zero other network I/O (verifiable: two short
  files). No telemetry, no phone-home, nothing reaches the author.
- The registry maps internal projects, so it is itself sensitive: README
  guidance is board permissions = whoever should see the portfolio, and the
  digest (the one artifact that leaves Monday) stays summary-level by design.

## Out of scope for v1, deliberately

Semantic/embedding dedup, Notion/Sheets/other adapters (on-demand v2), any web
UI or hosting, auto-discovery of any kind (scanners, log analysis), Slack app
packaging, multi-board setups.

## Launch plan (after build)

1. LinkedIn post + reddit post (r/ExperiencedDevs or r/artificial): the hook
   ("two people, same project, manager didn't know"), what the tool does, the
   three-step deploy, screenshots from the demo board, the trust line. Drafted
   in Omri's voice per his rules; his ChatGPT pipeline for the image.
2. Comment-driven v2: if people ask for other platforms, that demand is public
   validation and shapes the adapter order.
3. Claim discipline: it is a free tool by an internal-AI practitioner; no
   employer names in the tool, no adoption claims that do not exist.

## Build order

1. Board schema finalized as column list + template board built in Omri's
   Monday (he exports/shares the template; only step needing his account).
2. `prompts/interview.md` (the interview text is the product's heart; write
   it first, both doors share it).
3. Skill wrapping the interview + Monday API write + dedup-on-intake.
4. `wbw.py` digest + dedup + tests + Action example.
5. README + examples + screenshots.
6. Repo public on Omri's word; then posts.
