# who-builds-what v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the free who-builds-what kit: Monday-based AI-project registry with an AI interview (two doors), dedup + configurable-cadence manager digest script, README, and examples.

**Architecture:** No servers. A Monday board is the store (org-owned). The interview is prose (a paste-anywhere prompt and a Claude Code skill that also writes via Monday's GraphQL API). One stdlib Python script does dedup and digests; all pure logic is offline-testable, network isolated in one thin function.

**Tech Stack:** Python 3.10+ standard library only (urllib, json, argparse, unittest). Markdown prose artifacts. Monday GraphQL API v2. GitHub Actions for CI.

## Global Constraints

- Python: standard library ONLY, no third-party imports anywhere.
- The interview records data CATEGORIES, never actual data, keys, or PII (spec: no-secrets rule); both doors carry the rule verbatim.
- No employer names in any artifact. No adoption claims.
- Trust lines in README verbatim per spec: entries live in the org's Monday; interview runs on the org's own AI accounts; the script calls only Monday's API with the org's token, zero other network I/O; no telemetry.
- Config surface is exactly: `--cadence daily|weekly` (default weekly), `--stale-days N` (default 60), `--dedup-threshold F` (default 0.35). Nothing else.

  5. Offer the grill (same five areas as the prompt file).
  6. Report back to the user with the item's URL.
